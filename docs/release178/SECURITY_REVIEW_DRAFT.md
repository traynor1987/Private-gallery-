## Security properties inspected

- **Catalogue authority and persistence:** bounded validated definitions contain no credential API. Primary handles capture key identity, authentication epoch and presentation/transfer generations; operation key copies are wiped; commits recheck authority under the existing revocation gate. Hidden uses the original HiddenSession authority and broker gate; keys remain in the parent. Corruption is refused. Writes stage ciphertext and promote atomically. Hidden VPN/Tor catalogue records are distinct and authenticated; primary has separate AAD/storage.
- **PWA requests / SSRF / DNS:** metadata accepts public supported addresses, requires same-origin manifest/start/scope/icon resolution, declines redirects and credential-bearing URLs, and excludes cookies, origin Authorization and ambient caching. Primary uses an already owned Network's socket factory and DNS, with public-address checks. Hidden uses the authenticated localhost proxy; its VPN side resolves through its immutable Network and filters addresses, while Tor uses the established private Unix SOCKS path and remote origin resolution. No new ambient-origin-DNS fallback was found. Existing transport policy remains a dependency; this review does not turn source inspection into packet evidence.
- **Bounds and cancellation:** metadata responses are capped at 128 KiB, request and overall operation deadlines are bounded, and an authority watcher cancels calls. Images are decoded with dimension checks, normalized to at most 64 px / 6 KiB PNG and stored within encrypted records. Editor dismissal discards publication but does not immediately abort a blocking metadata request; the documented deadline/authority cancellation applies. JVM interceptor tests are useful for headers/redirects but cannot prove live DNS routing.
- **Launch and presentation:** saved IDs are resolved again against the owner-bound store before launch. Browsing uses the existing Primary session or current Hidden native profile and immutable selected transport. App scope is metadata with a visible outside-scope indication, not a security sandbox. Open-tab binding is cleared on browser retirement. Existing launch-time metadata may persist in an open tab after catalogue edit/removal; no per-app credential isolation follows from the app name or chrome.
- **Session honesty:** Primary uses one shared browser cookie profile; Hidden tabs share the current ephemeral profile. Encrypted definitions do not persist Hidden cookies. No persistent Hidden login or per-app cookie-clear guarantee can be approved without an independently reviewed implementation. Reauthentication must bind one launch to unchanged saved identity and original authority, and be tested after switch/lock/re-unlock.
- **Uploads and documents:** existing upload chooser checks originating view/origin/generation, and Hidden reads encrypted content through revocable descriptor callbacks rather than a plaintext temporary document. App switching and existing grants require final affected tests. Merely adding document MIME types is insufficient: document parsing/preview, retrieval, size limits, encryption, trash/restore and cancellation must be reviewed together.
- **Screenshots and upgrade:** screenshot capture must check existing capture policy, explicit confirmation and original tab/session at capture and encrypted commit; no public-file fallback. Upgrade evidence must use the original signing identity and preserve pre-existing encrypted media and Recently Deleted while adding private-app storage. These checks remain pending final implementation.
