## Security strengths supported by source

* The native child must claim a current parent-held Binder capability, validate an own-UID VPN Network, bind to that exact Network, select dedicated directory roots, and receive the no-bypass proxy completion before constructing its first WebView (Activity lines 197-235). It never clears or replaces the process binding. Unsupported provider features abort initialization.
* VPN proxy origin DNS and upstream sockets use the immutable Network. Resolved addresses are checked before connecting; HTTPS/WSS retain end-to-end TLS through CONNECT. HTTP request bodies are copied rather than reconstructed as GET. Proxy credentials are stripped from forwarded origin headers. The proxy has no DIRECT alternative.
* Synchronous HiddenSession revocation marks authority invalid and signals the claimed child process before deferred broker cleanup. Broker cleanup closes proxy streams, OkHttp calls and upload pipes, clears grants, and fences encrypted repository publication against the old authority. This is materially stronger than relying on heartbeat alone.
* Tor origin requests use private filesystem Unix SOCKS with DOMAIN names. The browser proxy resolver throws instead of resolving origin names locally. Tor native mode disables JavaScript and worker networking. The full app package is routed to a v4/v6/DNS TUN sink, with no packet forwarding or allowBypass. Only the separate authenticated numeric relay bridge calls protect, before remote connect; hostname relay requests are refused.
* The sink is retained while Tor/browser lifetimes are still observed. OS route loss leaves the child's dead immutable Network pin. Separate nonexported processes, fresh generation roots/profiles, kernel lifetime locks, durable cleanup jobs and encrypted separate mode library records support Primary/Hidden/Tor separation. Library commits use HiddenSession authority and distinct authenticated record IDs.
* Uploads require explicit selection and separate egress confirmation, return narrowly scoped nonexported same-UID provider URIs, and stream decrypted chunks through revocable pipes. Repository transfer-source checks revalidate vaultOnly restrictions. TLS error callbacks cancel. Device permissions and client certificates are refused.

These are source properties, not proof of actual Chromium/provider/socket behavior on the target OS.
