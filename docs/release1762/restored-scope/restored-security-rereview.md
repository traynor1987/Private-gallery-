## Important remaining source findings

1. **Delayed child background/death delivery can still discard the actual background deadline.** `MainActivity.kt:1092–1106` returns at `if(mainPresentationStarted)return` for BACKGROUND/DEATH as well as explicit RETURN. `onStart` (`1143–1158`) marks Main started and calls Hidden `onForeground`/Primary `onForegrounded` before a child event necessarily reaches Main's posted callback. Broker `end` posts `onPresentationEnded` asynchronously (`HiddenVpnBrowserBroker.kt:187–188`); child death delivery is asynchronous as well. If Main starts before that delivery, the previous background timestamp was never registered, its foreground check sees no deadline, and the late event is discarded. An elapsed Hidden timeout (or immediate policy) can therefore still be bypassed on a delayed return/death callback. Source race; no runtime reproduction claimed. Minimal safe fix: retain child foreground-loss timestamp in parent handoff state independently of UI start, consume it before foreground deadline evaluation, and handle a late BACKGROUND/DEATH event by enforcing already-expired authority without placing an actively foreground Main into background. Preserve distinct explicit RETURN behavior. Add delayed-delivery tests with Main already started, stoppedAt before each configured timeout, and actual Main→child→Home/kill→return ordering. Current `HiddenVpnHandoff1762Test` sets mainPresentationStarted=false before every background/death policy assertion, so misses this case.

2. **Persisted deletion job registration failure is silently ignored.** `HiddenVpnStorageCleanup.kt:102–105` ignores `JobScheduler.schedule`'s result, and `prepare` proceeds to admit WebView/storage after calling it (`47`). If registration returns RESULT_FAILURE, a later simultaneous parent/child process death loses both in-process cleanup callbacks and leaves the durable sensitive-data root without the promised persisted cleanup job until another Main launch. Minimal fix: require RESULT_SUCCESS before admitting the session, fail closed and clean/release the newly created root on failure, and ensure rescheduling failures remain visible/retryable. Add an injected scheduler-failure test plus a real scheduled-service/parent-process-death cleanup test. This is a source reliability hole in the newly claimed independent deletion guarantee, not evidence any job registration has failed in CI. Ordinary OS force-stop restrictions should also remain explicitly outside any immediate-erasure guarantee.
