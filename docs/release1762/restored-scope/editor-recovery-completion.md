# External editor recovery implementation

EV-01 source fix: Activity-only ticket state now has a durable encrypted recovery receipt in an independent per-origin no-backup directory. The existing originating vault key and existing authenticated AES-GCM record implementation seal original ID, public export URI, selected imported result URI, verified imported item ID and saved status. No PIN/key/session/old operation authority is stored. A domain marker and record ID are authenticated. Receipts are read only when that exact vault is selected and unlocked. Actual Activity recreation with pending receipts revokes retained Primary and Hidden authentication and routes to lock; process restart already starts locked.

A receipt is written before editor/picker launch. The MediaStore export path records its exact URI before publication, not in the later Activity callback. An unsuccessful publication can leave a conservative receipt for an absent pending row; it cannot lose a published URI. Cancel removes the temporary lease file and presentation but retains the encrypted receipt. Reopening the same originating photo within the authenticated Activity reuses the exact outstanding receipt and URI. A subsequent Activity can also recover it after authentication; no Samsung callback is promised and edited photo selection is repeated explicitly. Cleanup is available before importing as well as afterward. A separate explicit acknowledgement can forget a receipt while warning that public photos, caches and cloud copies may remain. Normal dismissal never claims deletion. Repeat Gallery export/open reuses the known export URI; it does not overwrite a published-copy receipt or create a second fallback copy. An inaccessible URI stays recorded conservatively until explicit acknowledgement; Gallery-created unknown copies remain outside app inspection. Save as New and explicitly confirmed verified Replace continue using the production import verifier. Before import the encrypted receipt is durable; the encrypted destination index atomically carries a deterministic operation marker as its source reference. Fresh recovery queries only the original vault and verifies the marked payload hash before presenting the save as complete. It inspects original retained/Recently Deleted state and never silently repeats replacement. An interrupted retry reuses the verified marked copy even when the user changes SaveNew/Replace selection. Receipt update failures retain an inspection warning instead of overwriting it with temporary cleanup status.

## Remaining acceptance limits

Physical Galaxy Fold/Samsung edit-only handoff/public fallback/picker/result permission behavior and actual process termination/font/locale lifecycle acceptance remain pending Android/owner evidence. Orientation alone may be handled by manifest configChanges and is not asserted to recreate. The app does not persist provider read permission or import automatically on a restored callback: the user selects the edited result again after authentication. A crash between verified import and receipt saved-state update leaves an older receipt; encrypted repository marker reconciliation prevents another import and reports actual original state. Public receipt retention is durable; Samsung/cloud cache deletion cannot be verified. No version, credential format, PIN, key, package or certificate changes were made.
