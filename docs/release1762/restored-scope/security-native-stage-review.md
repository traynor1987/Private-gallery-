## Important remaining native-VPN revocation gap

The immutable owned-WireGuard process pin prevents direct-route fallback but does not revoke Hidden authorization. Native WebView WebRTC/UDP or another protocol that bypasses the HTTP proxy is not governed by proxy valid() checks. `HiddenVpnBrowserBroker.end` closes tracked HTTP sockets/calls/pipes, then allows up to five seconds before child kill; the child permits a three-second asynchronous clear interval. A Hidden-only lock while WireGuard remains active also relies on child/runtime polling before process termination. Existing native sockets can therefore retain route capability during the revoked lifetime; destroying WebViews is not an established synchronous network revocation boundary. This is a missing source enforcement guarantee, not a packet leak observed by this reviewer. Activation=false contains exposure in the reviewed production path.

Minimal conservative fix: distinguish explicit still-authorized Done from authority loss/lock/background/death. On revoked native-VPN lifetime, promptly kill the live authenticated child using Binder/PID-safe ownership and rely on durable offline owned-root cleanup rather than requiring graceful WebView clear acknowledgement. Deliver Hidden lock/authority revocation to the owner immediately, rather than depending only on 250–500 ms polling, or synchronously revoke the dedicated transport. Only explicit Done while authority is still current should use the bounded graceful clear path. An actual ongoing WebRTC/UDP probe must span Hidden-only lock with WireGuard deliberately remaining alive; assert old-child death and absence of post-revocation egress. Slow HTTP response closure does not cover this protocol boundary. Native Tor has an additional deny-all sink and synchronously retired protected bridge, but its own post-revocation packet proof also remains required.
