## Important EV-01 — Published external-edit receipts disappear on recreation or cancellation

`MainActivity.kt:243–255` keeps ExternalTicket and result-launch owners only in Activity fields. There is no external workflow state in retained state or saved-instance restoration. `MainActivity.kt:367` stores the published MediaStore URI only in that ticket. `HiddenPhoneExport.kt:29–35,67–76` recovers pending rows only and removes the publication journal entry after releasing the row publicly. This is appropriate for avoiding unrequested deletion, but supplies no authenticated recovery receipt for this editing workflow.

Concrete flow: explicitly consent to Gallery export, let the verified row become public, launch the external editor, then recreate MainActivity or kill/restart its process before finishing import/cleanup. The replacement Activity has neither ticket nor captured launcher owner, so a delivered result is ignored and reopening the source starts a fresh ticket without the published URI. The public photo survives while the app loses its exact-origin return/cleanup workflow. A death after encrypted import commits similarly loses the import receipt and can cause an unnecessary duplicate on manual retry. This remains the published-recovery gap identified in the older Samsung audit; discovery and failure-message corrections did not resolve it.

Ordinary Cancel also drops the known published URI: `MainActivity.kt:290–294` clears the ticket and deletes only the app-owned temporary file. `ExternalEditingDialog.kt:65–71` exposes public cleanup only after a successful import, and `MainActivity.kt:419` rejects cleanup before saved. An abandoned external edit therefore has no in-app cleanup action for its known public export. Public-copy consent does explain exposure, so this is a concrete restored-scope workflow/cleanup omission, not a claim of covert export or false cloud deletion.

Manifest qualification: `AndroidManifest.xml:57` handles orientation, screenSize, smallestScreenSize, screenLayout, keyboardHidden and density. Ordinary folding/rotation is consequently not established as a recreation trigger. Explicit ActivityScenario.recreate, process death, and unhandled configuration changes remain relevant; no physical Fold reproduction is claimed.

Required correction: retain nonsecret workflow routing through Activity recreation and preserve an encrypted, exact-origin-bound published-export/import receipt durably. Restore controls only after fresh authentication to that originating vault, with newly captured authority; never persist keys, plaintext, old authority closures or grants. Offer confirmed cleanup of a known export even when import is abandoned, or retain a recoverable receipt when closing. Journal receipt publication and verified imported identity across commit/UI-delivery interruption, while leaving deletion explicitly user-authorized. Add recreation during editor launch/export, published-row recovery, post-import-commit recovery, cancel-before-import cleanup and wrong-vault restoration regressions. App-cache lease expiry/job cleanup does not recover a published MediaStore receipt.
