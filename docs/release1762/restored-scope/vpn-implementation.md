## Native browser capabilities

Native WebView networking supports page JavaScript, fetch/XHR/body methods, ordinary forms, cookies/storage, service workers and HTTPS CONNECT without reconstructing request bodies in shouldInterceptRequest. URL policy still denies non-http(s), onion in VPN, numeric/private-looking names and nonstandard ports; proxy checks resolved destination addresses. TLS errors and client-certificate errors cancel. Native web permissions/geolocation are denied. Tabs, ephemeral history/bookmarks, desktop user agent/layout, loading/error state and session clear are included.

Website alert/confirm/prompt/before-unload, explicit upload confirmation, download confirmation, website HTTPS Basic auth and POST-resubmission confirmation use shared GalleryAlertDialog. Pending callbacks cancel on owning navigation, tab change/removal, session stop or network loss. Credentials/prompt text are cleared from state on close.

Downloads are expressly **confirmed fresh GET media saves only**. Parent performs pinned socket/DNS request with bounded current-profile cookies/user agent, no redirects/retries/direct proxy, verifies completeness/media validation, imports into encrypted HiddenRepository, and verifies saved object. Commit is fenced by both original authority and broker gate. Child receives actual async success/error status via CHECK heartbeat. Existing DownloadListener callback never silently replays unknown POST; it explains POST/blob/one-use limitations.

## Real limitations still requiring resolution/evidence

1. Full arbitrary POST-response/blob/one-use download parity is unavailable through Android's DownloadListener API, which supplies no original body/response stream. A transparent CONNECT proxy cannot inspect encrypted response bodies. Supported GET scope is explicit; this is not full browser-download parity.
2. Production network-security config still blocks public cleartext HTTP origins. Preserved rather than broadening Primary's global policy. Debug fixture permits reserved fixture.invalid only. Public HTTP native browsing remains an unresolved capability decision/architecture requirement.
3. Proxy authentication behavior must be observed with the packaged provider, including HTTPS CONNECT, service workers and credential caching. Sources support HttpAuthHandler, but this implementation has no successful provider/runtime proof yet. Failure has no DIRECT fallback.
4. Process pin + proxy cancellation + process kill implement revocation; no claim of zero packets at the exact instant an independent Hidden Authority flips before its owner executes close. Test explicit lock, stale epoch, Network loss/replacement, permission revoke, parent/child death, task removal and mode-switch races with packet capture.
5. Browsing provider data is app-private and generation-isolated, not an encrypted replacement for WebView's cookie/cache databases. Clear is asynchronous; process exits immediately and next authorized cold process removes retired profile containers before load. No profile is reused. Verify provider persistence/cleanup after crash/lock.
6. Child UI feature/large-font/Fold verification and Basic auth/form-resubmission website cases remain unexecuted. Native website permission requests remain denied, certificate selection unsupported, popups blocked. No request to weaken those policies was inferred.
