# Samsung external editing audit

Read-only source review of private-gallery at the requested HEAD 5b6be831. No physical Samsung/Fold testing or runtime compatibility claims. No repository edits or test execution.

## Main missing functionality

1. **Compatible editor discovery is absent.** `MainActivity.launchExternalEditor` only resolves `ExternalEditorIntents.samsungEditor`, hardcoded to `com.sec.android.gallery3d`. It never uses the generic editor helper and cannot offer another installed compatible editor. Its label always says Open Samsung editor even when Samsung is absent. Exact fix: introduce a resolver for `ACTION_EDIT` with actual content URI and image/png, retain exported/enabled/permitted matching activities, deduplicate explicit ComponentNames, rank Samsung Gallery first, show only those editor targets, and use explicit intents for the chosen component. Do not use SEND/VIEW discovery for the editor list. No candidates should display the public Gallery fallback and manual reimport path. Add discovery/filter/order/no-candidate tests with synthetic ResolveInfo inputs or fixture activities, including VIEW-only and SEND-only unrelated receivers.

2. **Published-export recovery loses the workflow.** `ExternalTicket`, the selected URI, original identifier/domain, launcher owners, and public export URI live only in MainActivity fields. They are not saved in ProtectedSessionState or encrypted durable state. HiddenPhoneExport reconciles only pending rows and intentionally leaves published rows. On activity recreation/process death the exported public copy remains but the app cannot resume its workflow or offer cleanup for that known URI. Exact fix: retain nonsecret workflow state across configuration recreation; persist an authenticated encrypted origin-domain-bound recovery record for published URI and import receipt; require unlocking that exact origin before restoring controls; never revive previous authority closures; discard/wipe on panic. Journal a publication reference before releasing the transaction and track verified imported item ID so import-committed/UI-interrupted recovery does not create an unnecessary duplicate. Tests should recreate the activity during external launch and export, and simulate published-export/import-commit recovery without allowing a primary unlock to restore hidden origin controls.

3. **Verification failure messaging overpromises.** `saveExternalResult` can report failure after import or replacement commits (the post-import allowed() check or a later verification can fail). `ExternalEditingDialog.commit` then says Original retained for every failure, although a committed replacement can already have moved it to Recently Deleted. MainActivity itself more accurately says inspect verified copies before retrying, but that message is not set here. Exact fix: return a structured result distinguishing no commit, imported-copy committed, and replacement committed, or use a neutral failure message directing inspection rather than asserting retention. Exercise lock/epoch change immediately after repository publication and immediately after replacement publication.

## Already implemented in source

- Read-only expiring FileProvider URI backed by a sanitized random-name app cache copy; no writable decrypted original exposed. Direct Samsung EDIT is attempted only after resolveActivity, and launch exceptions lead to fallback instructions.
- Explicit user-confirmed MediaStore fallback. ExternalPhotoExport uses HiddenPhoneExport: pending insertion, SHA-256/size readback verification, fsync, guarded publication, pending-row crash recovery. Opens exported photo through Samsung ACTION_VIEW and explains tap Edit. If Samsung VIEW cannot resolve, instructions remain manual.
- Photo Picker manual reimport; preview bounded source read, sanitized result, fresh originating-vault authority checks; hidden origin cannot fall back to primary.
- Save as New is an explicit default action; Replace Original has a separate confirmation and verifies encrypted copy before moving original to same-domain Recently Deleted.
- Temporary file deletion/revocation on cancel or successful import; provider rejects access after 15 minutes; job and startup cleanup remove expired files. Scheduled physical deletion is best effort, so UI wording could say access expires rather than imply guaranteed disk deletion at exactly 15 minutes.
- Public export explanation and confirmation, post-import cleanup request for known MediaStore URIs, separate explanation that editor caches/cloud copies are outside app control.

No activity recreation/process-death recovery test or compatible-editor discovery test exists in the inspected coverage.
