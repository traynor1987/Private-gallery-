## Important IR-6C093-01 — authorized full-screen document picker cancels its own upload

Locations: `app/src/main/java/uk/co/traynor/privategallery/ui/BrowserV2Home.kt:424-426`, cancellation implementation at 319-333, launcher at 334-377; `ui/BrowserDeviceSelection.kt:30-49`.

The newly added ON_STOP observer calls `cancelUpload()` whenever a website file callback is pending. Opening the explicitly selected system ACTION_OPEN_DOCUMENT Activity normally stops the covered browser Activity. Consequently an ordinary authorized sequence is: website chooser A → owner chooses device → reserved system picker opens → browser receives ON_STOP → cancelUpload cancels A and clears pendingFileResult → picker returns the selected URI → retained reservation consumes the result against the already-cancelled owner. A gets null and no upload succeeds. The ownership security fix rejects stale results correctly, but currently also rejects the intended normal handoff. This is an Important complete-feature regression, not an established confidentiality bypass.

The new tests do not cover this ordering. BrowserPermissionOwnership1762Test.Registry.onLaunch records an entry without launching another Activity; direct BrowserDeviceSelection1762Test calls validate URIs without the production browser lifecycle. Their positive results cannot establish a working real system-picker round trip.

Preserve the immutable owner, registry reservation, post-I/O policy/document/tab checks and cancellation on genuine background/revocation/navigation. Distinguish the explicitly owned picker handoff from unrelated backgrounding using a bounded lifecycle-aware handoff; do not simply suppress all background cancellation. Require an actual full-screen system document picker round trip with a granted synthetic external document, plus Home/lock/navigation/replacement cancellation while the picker is open.
