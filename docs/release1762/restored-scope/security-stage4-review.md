## Source findings and disposition

If Main's start message runs after that interval but before dispatch of an overdue timer, onStart cancels the timer and broker pending-loss delivery is rejected as already consumed. No expiry check then occurs. This resolves the identified source race by inspection; the amendment must be committed, compiled and executed before that resolution applies to a final exact-source release. ## Encrypted persistent Hidden library

No confirmed Critical/Important defect found in `HiddenBrowserLibrary.java` or its reviewed parent IPC integration.

- Each operation obtains the captured Hidden authority, reads existing authenticated ciphertext before mutation, promotes only inside `session.commit`, syncs promotion, and checks current authority before returning. Failed read/decryption never defaults to an empty state and cannot overwrite an existing wrong-key file. The class-wide mutation gate serializes wrappers in the parent process; child receives no key or repository object. The production library is instantiated only in the parent runtime/broker; no unsupported cross-process writer was found.
- Data uses a dedicated no-backup root and HiddenRecordStore's AES-GCM authenticated kind/id domain. VPN/Tor use distinct fixed record IDs, separate preferences/defaults and bounded lists; Primary library is not read or imported. Ciphertext swapping between those modes fails authenticated identity checks. Original PIN/encryption formats were not modified for this library.
- Decode is bounded by HiddenRecordStore's 4 MiB metadata cap, at most 50 bookmarks/100 history entries, URL maximum 2048 Java characters, duplicate/unsafe URL checks, explicit version and trailing-data rejection. Plaintext encoding/decryption buffers are wiped. Immutable URL strings necessarily remain in authorized memory until released; child library state is cleared on termination.
- LIBRARY IPC (`HiddenVpnBrowserBroker.kt`, transaction FIRST_CALL_TRANSACTION+8) uses the established same-UID/claimed-child-PID capability and current-session checks, serializes mutations under broker gate, and does not accept arbitrary file paths or mode identities. Its response is list-bounded; normal maximum URL payload is approximately 0.6 MiB UTF-16 before modest JSON overhead rather than unbounded metadata size. There is no explicit parcel-byte cap or pagination; a worst-case supported URL/JSON and concurrent Binder-pressure Android test would strengthen this, but no definite overflow or isolation defect is established by inspection. Keep PREVIEW/LIST/library calls bounded and avoid claiming runtime robustness without that test.
- Host checks meaningfully cover same-key restart, wrong-key read/write non-overwrite, mode independence, defaults/preferences, list bounds, old-authority staged promotion rejection, concurrent wrapper updates, absence of plaintext and leftover staging. Android test covers integration/re-authentication and encrypted persistence. These test sources were inspected; they were not rerun in this review. Add corrupt/truncated/version/duplicate-record fixtures and maximal IPC response coverage when validating the feature.
- VPN history defaults on and Tor history off; disabling removes old history, explicit browsing-data clear retains intentional bookmarks and preference. This is now persistent encrypted library data, distinct from fresh cookies/tab/session profiles; user-facing claims must preserve that distinction.
