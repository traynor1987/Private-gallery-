# Modal source audit (read-only)

Scope: source inspection at release/1.7.6.2-ui-browser-polish, requested HEAD 5b6be831. No edits to repository, no tests or runtime/visual verification performed. Read MODAL_INVENTORY.md, shared shells/theme, modal call-site search, custom pickers, sheets, browser panel/legacy popup, Hidden restore/settings and dialog fixture tests. This is an independent risk review, not proof every modal is defective.

## Findings and minimal changes

1. **Prompt-template editor footer cannot adapt to narrow/large-text layouts.** `ui/AiEditingSettings.kt:174` puts Reset, Cancel and Save in a non-wrapping Row outside the scroll viewport. Header is also outside scroll and unbounded. At large font sizes the three buttons compete for the cover-width budget; landscape+IME further reduces the scroll body. Replace footer Row with end-aligned FlowRow (or width-dependent stacked full-width actions), preserve minimum touch heights, and allow the header to scroll with the form if the available height is small. Verify the actual editor with the keyboard visible, not only the shared alert fixture.

2. **Vault/reference picker fixed chrome can starve the grid on short, large-text windows.** `ui/CreateImageSheet.kt:177-195` and `ui/BrowserV2Home.kt:808-836` keep title, explanatory text and footer outside the only scroll container (weighted LazyVerticalGrid), within bounded-height surfaces. As font scale increases or landscape height falls, non-scrollable chrome consumes the grid budget; there is no whole-content fallback. Browser footer uses another non-wrapping Cancel/Continue Row. Minimal adjustment: adaptive/wrapping footer; compact or scrollable introductory chrome; derive a bounded grid viewport from remaining available height and explicitly test nonzero visible grid plus reachable actions. Preserve lazy grid rather than wrapping it in an unbounded verticalScroll.

3. **Custom bounded restore surface bypasses shared decoration.** `ui/HiddenRestoreDialog.kt:43-46` duplicates width, shape and surface color, but omits the shared subtle border and tonal elevation. It also puts Cancel and confirmation inside the scrolling form, unlike the advertised pinned-action alert behavior. Replace only the non-authentication branch surface with `GalleryDialogSurface` (preserving safe-drawing padding and fullscreen keypad branch); use a bounded scroll body and separate adaptive footer if pinned actions are a requirement. Source is theme-aware already; this is a consistency difference, not a white-dialog defect.

4. **Legacy website popup overlay is omitted from inventory's explicit families.** `ui/PrivateBrowser.kt:603-615` draws `popupWebView` in a full-size Surface with a child WebView and floating close button. Close glyph has inherited tint and no opaque backing, so the website rendered beneath can undermine its contrast. No safeDrawingPadding is applied in this overlay. If legacy browser remains reachable, give the close action an opaque theme-aware container and safe-drawing inset, and document this app-owned overlay. Confirm back handling and keyboard restoration. If unreachable, explicitly record its inactive status rather than treating source-family coverage as active runtime coverage.

5. **Additional non-wrapping action rows need actual large-text checks.** `ui/TransferHistoryDialog.kt` has Resume/Retry and Cancel transfer inside a plain Row within each entry; the same constrained alert width has long labels. Convert to FlowRow or stacked buttons. This has a narrower source-level basis than a proven clipping report; capture its busy/error/resume states before declaring fixed.

## What is already covered in source

Shared GalleryAlertDialog routes alerts through selected app Material3 colors, shape, outline and default body scroll. GalleryDialogSurface sets matching bounded-dialog palette/decoration. Three bottom-sheet families use Compose Material3 with bounded scrolling content; menus use Material3. Native media date/time pickers explicitly choose selected-theme styles. Browser full-screen panels include safe-drawing and IME padding. Black media canvases are intentional. No newly discovered direct Android AlertDialog builder or PopupWindow family emerged from inspection.

## Verification gaps

`GalleryDialog1762Test` exercises a synthetic long-text shared alert at 1.6x font scale: cover light/dark, inner dark, landscape light. It checks bottom-body scroll, Continue visibility, cancellation, bounds and a single surface pixel. It does not instantiate the custom prompt editor, API setup, reference/upload grid, sheet, legacy child popup, restore destination form or transfer history rows; does not show IME; does not test hardware focus traversal/Enter/Escape, TalkBack, state retention across physical fold/unfold, landscape dark or inner light. A width/height fit assertion plus one pixel is not a visual contrast/layout audit.

Inventory's cited 117-case Android17 run is documentary evidence only in this review; I did not independently inspect its artifacts or rerun it. Physical Samsung keyboard, fold/unfold, OEM picker appearance and larger accessibility font scales remain unverified. Acceptance should use real component states in both selected themes against contrary OS theme, cover/inner/landscape sizes, text at least 1.6x and system maximum, with IME shown for every editable form. Assert actions and last content are reachable and grid/list viewports retain useful size; inspect screenshots, focus, dismissal and operation-state behavior.
