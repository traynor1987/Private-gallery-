## Important findings

1. **Browser handoff bypasses background timeout/lock policy.** `MainActivity.kt:1088–1095` returns from `onStop` whenever the interactive broker is active and the screen is interactive. This skips Primary `session.onActivityStopped`, Hidden `session.onBackground`, pending-auth cancellation and transfer cleanup (`1100–1114`). The child later stopping, receiving SCREEN_OFF or dying calls `HiddenVpnBrowserActivity.terminate` (`294–308`) / broker close, whose callback only closes `HiddenBrowserRuntime` (`HiddenBrowserRuntime.kt:138–140`). Neither delivers the omitted session background transitions. `HiddenSession.java:44–49,96–111` expires only after an explicit background timestamp; Main's next `onStart` calls `onForeground` without any preceding timestamp. Home from the child can therefore leave Hidden unlocked past its configured grace, including immediate-lock preference. Screen-off while Main is already stopped has the same missing session transition. This is a source defect, not inferred from a failed test. Fix with explicit foreground handoff ownership: child foreground/background/death notifications must apply parent session/background/cleanup policy exactly once, with normal child→Main return distinguished from app background; screen-off must revoke promptly. Test production Main→child→Home, screen-off, child kill and return after each configured timeout. The current live fixture uses a generic ComponentActivity and cannot exercise this path.

2. **Session-data clearing is initiated then immediately killed.** `HiddenVpnBrowserActivity.kt:302–305` invokes asynchronous `HiddenProfileCleanup.clear` and immediately kills its process. `HiddenProfileCleanup.kt:16–18` exposes the completion callback but the caller ignores it; parent broker close (`HiddenVpnBrowserBroker.kt:146–147`) also kills the child before a cleanup protocol. Thus “Closing ... ends ... session data” is unproven and normal exit can interrupt deletion, leaving cookies/site storage on disk until another successful startup deletes retired containers. A fresh random profile prevents reuse, but does not prove deletion or credential/temp cleanup at exit. Fix via fail-closed shutdown: revoke/close traffic synchronously, keep process pinned, acknowledge browsing-data deletion before normal exit with a bounded fallback, and have a durable retired-container cleanup mechanism for forced deaths that actually runs independently of opening this browser again. Test cookie/DOM/service-worker/cache data after ordinary close and forced parent/child death. Do not claim deletion from fresh-profile separation alone.
