## Source changes

- HiddenTorIsolationService.kt: app-owned full IPv4+IPv6 local VpnService, app UID inclusion, synthetic DNS, no allowBypass/exclusions/TUN forwarding. TUN packet reader discards all packets and exposes aggregate IPv4/IPv6/UDP counters only. Correct system SERVICE_INTERFACE binding preserves onRevoke. Foreground specialUse service is START_NOT_STICKY; manifest adds corresponding permissions, service entry and generic private notification. Teardown closes protected egress, waits for native browser/Tor processes to die before closing sink, then removes Unix socket directory. OS process death/revoke can remove a Network earlier; child immutable binding and strict Tor outbound proxy still have no origin/direct fallback.
- HiddenTorRelayBridge.kt: authenticated RFC1929 local SOCKS5 relay egress, numeric public IPv4/IPv6 targets only, never hostname resolution. Only this component calls VpnService.protect before connect and fails when protect fails. Bounded32 sessions, tracked sockets, cancellation and authority watchdog. It is separate from the browser proxy and has a separate unguessable credential. Authenticated numeric requests represent Tor relay destinations, not website-origin requests.
- HiddenTorService/Connection.kt: legacy connection keeps its prior default TCP configuration for legacy packaged-Tor tests. New isolated configuration is applied before native TorService.onCreate; native startup is deferred until binding supplies configuration. Sets private filesystem Unix SocksPort plus supported authenticated Socks5Proxy to the protected numeric relay bridge. Native Tor links parent Binder death to immediate process termination. UNIX_READY requires established circuit and actual control-reported exclusively Unix SOCKS listeners. No per-FD Tor hooks, new native stack or binary change.
- HiddenTorSockets.kt: private Unix SOCKS5 DOMAIN origin requests. Numeric socket path is bounded below Unix path-length limit, within canonical app data/ts0700 directory. No visited-site Android DNS. No browser-facing Tor TCP SOCKS listener in isolated mode; ordinary other-UID apps cannot traverse the directory.
- HiddenVpnProxy.kt: existing body-transparent HTTP/CONNECT proxy generalized to mode-aware URL checks and private Unix Tor upstream. Original request body/TLS streams are forwarded unchanged. VPN Network transport remains unchanged. Both proxy/relay authority watchdogs close stalled handshakes/streams without waiting on UI loop. No DIRECT alternative.
- HiddenVpnBrowserBroker/Activity.kt: claim includes mode; same shared UI/picker/tab/library/profile cleanup works for Tor and VPN. Tor actual WebView scripts are disabled, service-worker native networking blocked, native forms/multipart enabled through selected proxy; VPN scripts remain enabled. Library is mode-separated through existing encrypted helper. Tor GET media uses explicit authenticated local HTTP→Tor Unix proxy, no origin DNS, certificate overrides, retry or direct fallback. Same-path Tor HTTPS readiness must pass before connected/native launch. PREVIEW+7 and LIBRARY+8 preserved; new PANIC+9 authenticates parent callback. Immediate child black cover and shared three-finger PanicTouchGate/quick-lock preferences restored; parent panic uses captured authentication epochs. New child library uses bounded LazyColumn and compact slash JSON helper for Parcel bounds. Picker agent independently owns paging/asynchronous LIST/PREVIEW/chooser improvements.
- HiddenBrowserRuntime.kt: waits for old browser/Tor/sink lifetime to retire before any route change, confirms WireGuard release, obtains Android local VPN consent without provider config, establishes sink before Tor initialization, waits UNIX_READY and same-path HTTPS, then launches shared native child for both modes. Tor-only verification gate added. Normal close stops browser admissions/Tor before sink retirement. Desktop mutator renamed updateDesktopSite to remove demonstrated JVM setter clash; caller updated.
- MainActivity.kt: separate Tor VPN-consent request/result owner (no profile import and no WireGuard permission conflation), cancellation retires Deferred work but retains pending Android-result marker. Stale result cannot authorize another runtime. Existing background deadlines intentionally still apply while Android permission UI is foreground; after first permission approval/retirement, user unlocks Hidden and retries.
