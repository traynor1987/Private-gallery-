# NovaOS Preview widgets and media implementation plan

Goal: extend the existing preview launcher, preserving all current owner layouts, data, WebViews and preview signing identity.
Architecture: Compose additions over existing Home; independent versioned per-profile widget/search preferences; bounded validated layout-only JSON backups restored transactionally with rollback. Media adapters distinguish native controlled sessions from limited website metadata. Browser engine and production sources stay unchanged.
Baseline: 554e30217d8497f6068f17c04caa96045395c954, preview0.5/code5. Next preview0.6/code6, same package/key, API37.
Owner explicitly requested autonomous execution; design decisions below implement that approved scope without another approval gate.

1. Recovery: verify published0.5 SHA/certificate and remote head; inspect local writers and preserve work; acquire local cooperative ownership marker; use remote expected-head leases. No force push/reset/new branch.
2. Widget model: pure grid/collision/resize policy (4 columns, bounded rows/page); separately persisted widget records with type/id/page/position/span/config/stack/order/active index. Tests first for bounds, collisions, missing types, reflow and stack compatibility. Grid slots separate from existing shortcut grid so no owner shortcut positions are erased. Widget area scrolls in bounded Home content, never over Dock/navigation.
3. Widget Centre and Home editor: clock/date, Now Playing (three sizes), recent apps, Nova Mind/Calm Now, local Quick Notes and local Search. No weather/calendar/tasks without sources. Drag long-press moves with snapping; handles resize, accessible move/size controls, cross-page move, Undo removal. Compatible stacks share one slot, swipe pages, persist index/config, reorder/remove/delete.
4. Native media: expose genuine calm-sound MediaSession/position and controls. Website adapter retains existing public Media Session metadata only; no DOM scraping/new arbitrary JS/provider bypass. Unknown capabilities visibly disabled; Return always available for retained app. Keep web audio lifecycle.
5. Video: retained explicit user-selected local video with native controls/internal movable resizable mini player and supported Android PiP; use documented WebChromeClient custom-view callbacks for website fullscreen, internal mini only for non-restricted source callbacks. YouTube/unknown website PiP disabled with explanation; no stream extraction/Premium bypass. Test eligibility, close, ownership and aspect/clamp policy.
6. Search: local apps/folders/Home/widgets/settings/games/recents/Mind actions; category filters, history/clear, keyboard search; optional explicit web-search action only. Never index notes/journal/production data.
7. Backup: export explicit allowlisted layout metadata and installed destination identifiers, no cookies/tokens/journal/Quick Note text. Strict schema/type/count/size/URL/path checks; SAF selection, preview/confirm/cancel, snapshot both preferences, rollback if any write fails. Custom wallpaper configuration references local-only filenames, export optional bounded image separately only if supported; never accept arbitrary paths. Document same-device image availability and fallbacks.
8. Internal lock: optional demo overlay with wallpaper/clock/date/brand, simple unlock, disable setting, generic media source only; hide underlying content and semantics; no competing PIN/biometrics, never claim encryption. Lock/restore cancel browser UI and hide media surfaces. Future authentication interface explicitly not production auth.
9. Verification/release: host policy and malformed-backup checks first; local app/test assembly and baseline/current certificate verification; independent review; focused API37 upgrade/runtime checks once with exact results. Do not count infrastructure failure as pass. Publish raw development APK prerelease and verify public bytes. Record source SHA, final metadata SHA and handover.

Review focus: restore failure halfway through; mixed profiles and background media; widget large-text/Fold resizing; hidden lock content/semantics; stale/closed media ownership. All require explicit tests or accurately reported device limitations.
Media references: https://developer.android.com/reference/android/webkit/WebChromeClient ; https://developer.android.com/develop/ui/views/picture-in-picture ; https://developer.android.com/reference/android/media/session/MediaSessionManager . Own MediaSession token avoids global notification/media privileges.
