# Nova Chat Lite implementation plan

Owner authorises signed preview APK delivery and explicitly permits a safe launcher prototype if DOM filtering cannot be verified. Existing branch only. No private linked session/device is accessible in this workspace; live authenticated selectors and identifiers cannot be certified.

Architecture: native approved-list launcher with manually supplied canonical international phone numbers (no display-name matching), preview/profile-local persistence, a versioned built-in capability-only adapter, bounded structural booleans from explicit checks, and permanent native concealment while Friends Mode is requested. No production WORKING state without identity/filter proof; this build has no filtering adapter and cannot open a conversation safely. Ordinary WhatsApp requires explicit unfiltered exit; its retained WebView, cookies, UA and navigation are preserved. Sanctuary auto-entry uses this same guarded launcher.

Alternatives: guessing WhatsApp selectors or scraping message/contact data is rejected; screenshot-only evidence proves authentication, not DOM identity/filter coverage. Official click-to-chat can select a phone number but cannot guarantee excluded-list/search concealment, so it is not silently launched. Signed APK updates only; no remote executable adapters.

- [ ] Tests: canonical phone identity, duplicates, unknown contacts and all compatibility failures never certify WORKING.
- [ ] Native approved friend CRUD, local persistence, diagnostics without names/numbers; no body/token export.
- [ ] Existing retained view guard, pre-display concealment, route/Back/Sanctuary, lifecycle probe with stale-callback validation.
- [ ] Synthetic Android cases for launcher/unknown/guard/reload/recreation/DOM changes/Fold; retained browser/audio regressions.
- [ ] Version10, stable certificate, focused API37 CI, pinned code9 upgrade, raw prerelease APK and independent verification.

Limitation: no reliable live WhatsApp filtering implemented in this fallback; approved reading/sending stays disabled rather than showing an unfiltered surface. This does not claim success of authenticated chat filtering.

Owner steering: implement local inspector first. Supersedes automatic compatibility checks: no page inspection on entry/resume. Signed built-in v0.1 script executes only after Start; exactly3 samples,1000ms apart,3000ms callback timeout. Stop/cancel/generation/profile/navigation checks discard stale callbacks. Native schema admits fixed keys/values only and reserialises canonically before storing/display/copy; no raw page strings are exported. Numbers/IDs/names never read from row attributes. Geometry-only virtualisation hint, bounded open-shadow-root check, no scrolling; stable identity and scrolling behaviour explicitly UNKNOWN. View entire report before Copy; no automatic transmission. Friends launcher remains an unsupported prototype and permanently covers WhatsApp while requested.

Review rulings: only explicit Start inspects; no automatic probes. Reports use canonical closed-schema reconstruction, not raw JSON return. Internal aggregate signature compares fixed tag categories/child buckets/grid-cell presence; report does not assert DOM equivalence. Document navigation is distinct from unknown SPA navigation. View/Copy disabled during RUNNING to prevent preview races. Browser V1 guard is scoped to WhatsApp site and latched source tabs, not unrelated tabs; conceal before direct/history/redirect navigation and native configure. Existing conservative media-attribution suppression while a guarded source exists is retained to avoid displaying private unmatched session metadata; WebViews/audio are not paused. Owner-approved fallback remains opaque, never WORKING.
