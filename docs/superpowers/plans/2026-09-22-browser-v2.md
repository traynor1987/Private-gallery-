# Private Gallery Browser V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` task-by-task. Steps use checkbox syntax.

**Goal:** Replace Browser V1 with a stable, session-owned, multi-tab private Browser while preserving Vault and WireGuard boundaries.

**Architecture:** `BrowserSessionManager` owns WebViews and tabs; Compose renders snapshots and attaches a stable selected view. `SecureWebViewFactory` supplies every main/popup view. VPN, encrypted data and Vault import remain narrow adapters around existing approved implementations.

**Tech Stack:** Kotlin, Compose, Android System WebView, WebChromeClient/WebViewClient, existing WireGuard GoBackend/Vault crypto.

**Spec:** `docs/design/browser-v2-design.md`

## Global Constraints

- Preserve encrypted Vault formats, collections/favourite/Jenna semantics and permanent signer.
- Reuse official WireGuard GoBackend, profile storage, `BrowserVpnController` and `VaultImportCoordinator`.
- No JS bridge, TLS bypass, file/content access, mixed content or custom-scheme escape.
- Do not record Browser URLs, hosts, tokens, cookies, page data or media in diagnostics.
- Production verbose Browser diagnostics remain disabled.
- Physical acceptance remains mandatory before production release.

## Review Focus

- A state-only Compose recomposition must leave the selected tab WebView identity unchanged.
- A renderer-process death must destroy only the failed tab and never crash/lock-break the app.
- A VPN drop must stop new remote navigation/acquisition without clearing a loaded page.
- A popup must receive the constrained factory policy and a real WebViewTransport target.
- History/bookmarks/session restore must not leave plaintext private Browser metadata on disk.
