# Hidden selection, settings and background timeout correction

Owner requirements supersede CI589 exit-and-lock behaviour. Hidden selection now remains active across original device Gallery, original V1 WireGuard Browser and original Settings. Vault/Favourite select only authenticated Hidden repositories while this mode is selected. Settings has an authenticated, clearly separate Hidden section; Lock Hidden and use Primary explicitly leaves this mode. Process restart does not restore an unlocked Hidden key or selection.

The session has no fixed foreground60-second expiry. Independent non-secret Hidden timeout policy offers Immediately/30seconds/1minute/5minutes, default1minute. Backgrounding revokes existing operation epochs and prevents new operations; foreground return checks the deadline before clearing it. Repeated background notifications cannot extend the deadline. Manual Hidden lock shows its own PIN screen; explicit Primary lock and screen-off synchronously revoke Hidden. Automatic Primary timeout still locks Primary exactly as before, but does not shorten Hidden's own grace; the Primary PIN screen blocks access until Primary reauthentication. A retained Hidden session does not grant Primary credentials. Configuration recreation retains only in-process ownership; destruction/process death does not persist keys.

MainActivity's real lock path owns revocation, not a UI visibility flag. Root Vault/Favourite dispatch is guarded against Primary content composition while Hidden is selected, including route restoration after Primary reauthentication. External tabs hide scoped media and retire their old presentation operations without deleting the independent session key. Gallery Import captures actual Primary and Hidden authority and writes only Hidden; originals are retained. Hidden Move remains unavailable. Browser remains the unchanged V1 network implementation; encrypted-vault uploads and Browser-to-Primary saves are denied while Hidden is selected, rather than exposing a different vault. Use Add media or device Gallery Import for Hidden. Primary-mode Gallery/Browser/Settings behaviour remains unchanged.

Hidden PIN uses the same full-screen PinPage/LockSurface design as Primary with separate labels, asynchronous Hidden credential verification and independent keys. Old authentication failure/completion cannot revoke or unlock a newer attempt. PIN input is cleared on background/disposal and never persisted. Hidden windows keep FLAG_SECURE. TEST ONLY stays in the existing header/PIN title and launcher/version; no bottom banner is added.
