# H2 independent biometric convenience extension

IMPLEMENTED PHASE 2 CHANGE: optional independent biometric convenience after independently authenticated PIN enrollment. This records the owner-authorized H2 revision to H1-r2's previously mandatory secret-plus-biometric opening ceremony. It adds a separately versioned device-only envelope. It does not revise F1 schema-1 PIN/recovery slots, the catalog, or frozen vectors. It has no Primary alias/root/preferences dependency.

## Canonical wire encoding

All integers are big endian. Version 1 has exactly 96 header bytes and 48 body bytes (32 encrypted master bytes plus 128-bit GCM tag). The entire header is AES-256-GCM AAD. Parsing requires exact supplied opaque domain/master/slot IDs and positive generation before the one deterministic Keystore lookup. Unknown versions/algorithms, length/context mismatch, trailing bytes and reserved-field changes are rejected. Metadata is untrusted until AEAD and current descriptor/index/catalog validation succeed.

| Offset | Field | Value/width |
| --- | --- | --- |
| 0 | magic | ASCII `PGBIO001`, 8 bytes |
| 8 | envelope version | u16 = 1 |
| 10 | header length | u16 = 96 |
| 12 | algorithm | u16 = 1, AES-256-GCM |
| 14 | policy | u16 = 1, hardware per-use strong biometric |
| 16 | opaque container ID | 16 bytes |
| 32 | opaque master ID | 16 bytes |
| 48 | opaque slot ID | 16 bytes |
| 64 | generation | u64 in 1..2^63−1 |
| 72 | nonce | 12 provider-generated bytes |
| 84 | master length | u16 = 32 |
| 86 | tag length | u16 = 16 |
| 88 | body length | u32 = 48 |
| 92 | reserved | u32 = 0 |
| 96 | ciphertext and tag | exactly 48 bytes |

Alias is `pg.device.slot.v1.` + exact lowercase hex(container ID) + `.` + lowercase hex(master ID) + `.` + lowercase hex(slot ID). Every ID contributes exactly 32 hex characters. The alias is neutral opaque metadata, not a secret or authority. The adapter never enumerates aliases, falls back to Primary, replaces an existing alias, or generates a key during decrypt.

## Concrete adapter and controller obligations

`SecondaryBiometricSlot()` constructs only the real Android Keystore backend. The internal backend seam exists for synthetic tests and is not a public alternative policy.

| Call/property | Contract |
| --- | --- |
| `prepareEnrollment(identity, slotId, generation)` | Explicit PIN/session-authorized enrollment only; fresh random slot ID. Returns `PendingEnrollment` with `cipher`. |
| `finishEnrollment(pending, authenticatedCipher, master)` | Callback must return the identical Cipher instance. Single use even on failure. Copies/wipes its mutable master input copy; caller retains original ownership. Returns the envelope. |
| `PendingEnrollment.markInstalled()` | Transfer ownership inside the originating attempt/session guard immediately BEFORE pointer promotion, after the durable signed retirement plan owns failure cleanup. Prevents cancellation after promotion from deleting the selected key. |
| `PendingEnrollment.close()` | Cancels completion, wipes adapter buffers, deletes only this fresh enrollment's alias unless installed. Always close on cancel, finish failure, stale callback, or failed installation. |
| `prepareUnlock(identity, slotId, generation, envelope)` | Strict parse and context validation before existing-key lookup. Returns `PendingUnlock` with `cipher` and defensive `selectionDigest`. Missing/invalid key is UNAVAILABLE. |
| `finishUnlock(pending, authenticatedCipher)` | Identical Cipher and originating adapter required; single use. Returns owned mutable 32-byte master. Caller wipes after use or failed authority admission. |
| `PendingUnlock.selectionDigest` | SHA-256 of the exact captured envelope. Capture before close and compare to originally selected and currently active descriptor envelope. |
| `PendingUnlock.close()` | Cancels completion and wipes snapshot/digest buffers. |
| `SecondaryBiometricEnvelope.selectionDigest(...)` | Bounded pre-lookup context validation and exact full-envelope SHA-256; establishes no authority. |

Pending close and finish serialize; closing first prevents completion. A close cannot retroactively revoke already returned output. Controller must revalidate attempt ID/generation, originating session/operation and eligibility before finishing, before installing, and before publishing authority. The adapter never accepts a callback boolean as proof of authentication. Only successful Keystore `doFinal` on the exact per-operation CryptoObject proves cryptographic authorization. The UI must allow BIOMETRIC_STRONG only and no device-credential fallback.

The controller loads the optional bounded `biometricRecord()`; after unwrap it must use `validateAuthenticated(master)` and require the exact originally selected identity, slot ID, generation and complete envelope digest to remain active in the authenticated current purpose-9 descriptor/index/catalog before issuing session authority. An envelope's tag alone cannot establish current slot activity or defeat rolled-back external snapshots.

## Android policy and cleanup

Generation requests AES-256, GCM, no padding, randomized encryption, per-operation authentication and enrollment invalidation. Encryption initializes without a caller IV; the provider nonce enters the immutable header and AAD. One fresh key permits only one adapter enrollment encryption. Retry needs a new pending operation/fresh enrollment; no key invocation ledger is reset or reused through decrypt.

API 26–29 request per-use validity `-1`; API 30+ request `AUTH_BIOMETRIC_STRONG` with timeout `0`. Both require KeyInfo authentication-required, per-use duration, enrollment invalidation, exact AES/GCM authorization, and authentication enforcement by secure hardware. API 31+ accepts only TEE or StrongBox security levels; earlier APIs require `isInsideSecureHardware`. Software-only/unknown/weaker policy is unavailable, never a downgrade. TEE satisfies the inherited policy; the adapter does not promise StrongBox on every device.

Errors expose only fixed F1 failure categories, with no provider message/cause, context, ciphertext, master or logs. No plaintext master persistence occurs. Cleanup is best effort for controllable mutable buffers and owned aliases; provider/native copies cannot be reliably wiped. Process death during enrollment can leave an unselected opaque alias; it does not create session authority or permit alias reuse. No alias enumeration is implemented. Signed store maintenance retires only exact independently owned obsolete slot aliases. Process death before store maintenance assumes ownership may leave an unselected opaque fresh alias; no authority or reuse results. No owner data or enrolled Android biometrics are changed by tests.

## Evidence and remaining gate

TESTED EVIDENCE: focused Kotlin compile against Android 36; six JVM tests pass using synthetic independent AES keys. They exercise all 144 individual byte mutations, swapped Primary-style ciphertext, wrong key/context, unknown format, pre-lookup rejection, missing-key no generation, exact Cipher/adapter binding, consumed/closed callbacks and fresh-alias cleanup. This proves format and operation behavior, not biometric or hardware authorization.

Android instrumentation provides actual fresh random synthetic-alias KeyInfo inspection where preexisting device enrollment permits it, verifies hardware policy or unavailable cleanup, denies unauthenticated cryptographic completion, and checks missing decrypt never creates a key. Focused instrumentation Kotlin compile against Android 36/AndroidX succeeds; device execution has not occurred locally at this checkpoint. A refused enrollment branch is evidence only of fail-closed unavailable behavior, not successful hardware enrollment.

PHYSICAL ACCEPTANCE REQUIRED: owner PIN-authorized enrollment, real BIOMETRIC_STRONG CryptoObject wrap/unwrap, cancellation/background/late callback handling, enrollment invalidation, OEM/API combinations, and current-slot validation through the integrated controller. Distinct aliases identify keys, not humans: any Android enrolled biometric accepted by the device may authorize this slot. No distinct-person or universal OEM hardware claim is made.
