## Numbered source findings

### SEC179-1 — Important: default AI text contains the original filename

**Locations:** `core/evidence/EvidenceAi.kt:190–193`; origin in `core/evidence/EvidenceController.kt:115`; coverage blind spot in `app/src/androidTest/java/uk/co/traynor/privategallery/core/evidence/EvidenceAi179Test.kt:26–28,87–89`.

Registration initializes `Evidence.name` from `source.item.displayName`. `EvidenceAi.exactText` then includes `record.name()` in both its selected text accounting and the transmitted JSON `name` field, without distinguishing an owner-authored annotation from that default source filename. The default text-only request therefore transmits the acquisition/vault filename. Filename information can itself contain identity, place or other metadata excluded by the binding AI contract: **“No filename/location/unrelated evidence.”** Omitting `metadata.sourceName` and EXIF does not remove the same value carried through `Evidence.name`.

**Reproduction:** import/register an allowed original named `patient-Jane-London-clinic.png`, leave the initial evidence name unchanged, select it for text-only AI, and prepare the exact preview. Its selected JSON contains `"name":"patient-Jane-London-clinic.png"`; explicitly confirming sends that same value in the Responses body. The explicit preview and one-shot confirmation prevent automatic/surprise uploads but do not override the specified filename exclusion. The coordinator confirmed the exclusion is binding, while local filename metadata remains allowed.

The current AI fixture uses `PRIVATE_FILENAME_GPS` for the original and metadata but independently supplies the sanitized evidence name `Selected title`. Its privacy assertion therefore bypasses the production default naming path and cannot detect this disclosure.

**Required correction:** exclude filename-bearing names from the AI projection. The simplest bounded correction is to omit the name field entirely while retaining selected evidence IDs and the explicitly supported annotation/transcript fields; preserve local display names and export metadata. If owner-authored titles are retained, establish explicit provenance that cannot mistake a default/imported filename for one. Add a focused integration/projection regression with the actual default evidence name equal to a distinctive sensitive filename, distinct metadata/GPS sentinels, and assertions against both preview and exact transmitted body. Preserve exact consent binding and zero key reads/POSTs before confirmation.

### SEC179-2 — Important: direct plaintext export publishes source bytes before authenticated EOF

**Locations:** `core/evidence/EvidenceArchive.kt:105–117`; public destination integration in `ui/EvidenceLockerHost.kt:95–102`; underlying contract in `core/vault/AndroidVaultRepository.kt:245–272` and `core/evidence/EvidenceAccess.kt:147–160`.

For `plaintextConfirmed`, the archive writer selects the caller's `ReceiptOutput` directly, then sends original chunks through `zip.write` **inside** `reader.readVerified`, before its EOF tag/digest and outer live-state checks complete. The Host passes a writable public SAF destination directly to that path. In particular, the reused Primary legacy/nonchunked source deliberately uses BouncyCastle streaming GCM, which returns preliminary plaintext and verifies its GCM tag only at EOF. Its own comment restricts preliminary bytes to encrypted staging, never a viewer/provider. `EvidenceEgress.requireAllowed` checks current metadata/policy; it does not authenticate all original payload bytes before this write.

The eventual exception/no receipt and best-effort destination deletion are insufficient: an external provider can already have received and retained the unverified bytes. This violates the shared source-reader rule **“consumers cannot publish before readVerified returns.”** It also permits a failed late-tag original to leave a partial readable export outside the vault. The encrypted default path is not affected in the same way because it completes and seals private ciphertext staging before the picker/public copy. Authenticated opening and re-export of a sealed archive already demonstrate the appropriate pre-publication boundary.

**Reproduction:** register a sufficiently large, poorly compressible Primary nonchunked image/document, then corrupt only its stored final GCM tag without changing the catalogue fingerprint. Explicitly choose plaintext export to a recording provider whose deletion is refused. `readVerified` yields the original prefix and `ZipOutputStream` emits compressed original content to that provider; EOF then fails authentication. The UI reports failure and requests cleanup, but the captured partial ZIP contains recoverable original-prefix data. A smaller deterministic regression can use an `EvidenceSourceReader` that yields enough distinctive bytes and throws on EOF/after the consumer returns, and assert that no public output is admitted. The actual repository late-tag variant should also be covered.

Existing `writerOriginalActualSizeHashReaderFailuresAndStreamingRetirementNeverSucceed` checks that the writer throws for both modes; it does not inspect bytes already delivered. “No successful receipt” is weaker than the required publication boundary.

**Required correction:** complete source authentication and post-read owner/policy checks before exposing readable export bytes. Reuse a bounded ciphertext-only staged archive and authenticate its sealed contents before streaming explicitly confirmed plaintext, or provide an equivalently immutable authenticated snapshot. A preflight read followed by an unchecked reread of a mutable original is insufficient. Keep all temporary disk contents encrypted, retain cancellation/current-authority and source policy checks, preserve separate plaintext confirmation and same-document protections, and test late tag/hash/post-reader failure plus blocked-provider cancellation without early public bytes.
