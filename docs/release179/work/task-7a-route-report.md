### R2: liveness, actual failure time and independently ordered action receipts

Added `/evidence179/arm/<case>/<nonce>/<phase>/<token>` as an observation-only endpoint. Under the shared event-file lock it accepts exactly one uniquely admitted, unclosed slow stream and writes an `action-arm` receipt carrying the associated original POST identity and a fresh action token. It refuses a prior terminal event or duplicate arm. The Android test obtains it over its independent existing owned observation path; the POST under proof still uses the unmodified coordinator-returned `EvidenceRoute`.

Immediately before arming and again immediately before the action, the test requires its deferred request to be active/incomplete, with no recorded failure and no successful publication. The request worker captures `request_failed_elapsed_ns` in its actual catch block, rather than assigning a later time after `await()`. Cancellation and destructive actions record invocation time immediately before the corresponding operation; Tor's PID selection/verification is done before arming, not between the timestamp and kill. Successful publication is separately recorded and forbidden. Validator checks actual failure after invocation, a20second bound, and the remaining transport-retirement bound.

The arm request records device monotonic send/receive nanoseconds, and the independent receipt has host monotonic time. Its round trip brackets the host/device clock offset. Before accepting a terminal receipt, the validator conservatively requires host close monotonic time to be later than `host_arm + (device_action - device_arm_send) + 5ms`. This uses the upper bound of possible action time, not unrelated wall-clock comparison, and has an outward margin for precision/rate error. Host event ordering and nonnegative epoch/monotonic durations are additionally required. An overlapping/inconclusive timing observation fails; it cannot be promoted to causal close proof.

Fixture closure classification now accepts only observed read EOF, `BrokenPipeError/EPIPE32`, `ConnectionResetError/ECONNRESET104`, `SSLEOFError/SSL_ERROR_EOF8` or `SSLZeroReturnError/SSL_ERROR_ZERO_RETURN6`. Generic `SSLError`, including errno1, and other I/O errors produce `slow-io-error`; local timeout and normal completion retain their separate failure classifications. The validator requires the matching error type, errno and close-evidence category; generic TLS errors cannot satisfy `slow-closed`.

Regression coverage rejects both exact review probes (negative host duration; generic TLS1) for loss/revoke/death, actual failure before the action, host closure before the conservatively bounded action, absent liveness, successful publication and wrong arm token.
