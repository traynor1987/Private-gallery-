**Design only; implementation frozen.** Baseline is root's reviewed `18abaec525677cc82fb5f5fdb198b59a4f7eaa3b`; actual route source remains byte-identical to diagnostic source `29a2a7b0c3951cd8d4cdf77fe58be06ebfb235b9`. Original run41252039247 artifacts remain failed/incomplete and immutable. This design cannot repair or promote them.

## Decision and alternatives

Use a **nonce-bound, test-only ADB ordered-broadcast clock rendezvous at the existing action timestamp**. The instrumentation test reads actual `SystemClock.elapsedRealtimeNanos()` once; that same integer is both its existing `action_elapsed_ns` and the clock reply's `sample_elapsed_ns`. The host's original monotonic send/receive bracket therefore contains that exact action timestamp, without extrapolating a different device sample to the action. Intersect with the existing arm-derived interval, require consistency, and retain an additional conservative probe-upper-bound check described below.

* Periodic independent SystemClock samples would require a new justified relative-rate/drift bound, a sample-age policy and suspend treatment. They are unnecessary when the clock request can rendezvous at the already-instrumented action read.
* `/proc/uptime` adds an unproved equivalence and quantization conversion. Do not use it for calibration.
* Delayed EOF reads, sleep-and-retimestamp, midpoint offsets, lower-bound comparisons and accepting wide/inconclusive samples are rejected. The fixture continues reading and timestamping exactly as today.

This adds clock coordination to the existing runner/test; no production component, network/debug listener, new workflow, version change or new Android test case. All 153 frozen cases and other release controls remain mandatory.

## Ownership and one-shot protocol

Add `EvidenceRouteClock179.kt` under the same `app/src/androidTest/.../core/evidence/` package. Construct it inside `EvidenceOwnedRoute179Test.exercise`, in the actual instrumentation/target process. Dynamically register its receiver against the target context, with `android.permission.DUMP` required of senders, `Context.RECEIVER_EXPORTED`, a dedicated `HandlerThread`, and an action name containing a fresh per-invocation random host run nonce. No manifest receiver and no separate `.test` process: a manifest receiver must not be used to pretend it shares the instrumentation's pending state. The implementation records/verifies target package, instrumentation class, PID, UID and exact test classname. Debug build and API37 checks remain. Receiver has no action/coordinator/route callback.

The host starts one owned helper for each existing route invocation, selects exactly one ADB transport, and supplies fresh `evidence179ClockRunNonce` and expected serial through instrumentation arguments alongside the existing source SHA. Independently capture the selected ADB serial/transport and device boot ID before and after that invocation; the test reads its own boot ID and returns it. Capture host boot ID and monotonic clock implementation/resolution. PID/UID/classname and boot identity must agree across all replies and the Android receipt. Missing identity is a failure, not an anonymous calibration. The host serial is transport metadata, not an assertion that Android can read a privileged serial property.

Protocol uses bounded, strictly parsed extras and a single base64url-encoded UTF-8 JSON result (no shell-built JSON). Every successful reply contains `schema=1`, source SHA, host run nonce, random host request nonce, exact case/method/classname, route nonce, phase, arm token/sequence, target package, PID/UID, device boot ID and sample counter. Unknown fields/types, duplicate keys, malformed framing or more than one result are rejected. Command arguments are a subprocess argv list; validate shell-bound identifiers before invoking `adb -s SERIAL shell am broadcast`.

1. Register on entry; expose bounded `STATE` polling only for the helper to discover readiness. After real admission and the existing route-specific arm exchange, install exactly one immutable pending identity `(case, route_nonce, phase, arm_token, arm_sequence)`. No later-phase identity can overwrite an outstanding phase.
2. `STATE` returns `not_ready` or that identity. It never supplies calibration or changes state. Polling is bounded by the existing invocation timeout and records its failures. The helper then issues exactly one `SAMPLE` for the identity with a fresh unpredictable request nonce. No retry/replacement sample is allowed after a phase has accepted its `SAMPLE`.
3. The receiver validates source/run/case/phase/arm identity and atomically claims the pending phase. It uses `goAsync()` and bounded coordination on its dedicated thread; neither Android main thread nor broadcast dispatch may block awaiting the test. It signals only that a clock request is waiting. The test's coroutine waits with a one-second deadline, then repeats all existing work-active/not-completed/no-failure/no-publication assertions.
4. At the exact existing action timestamp location, `clock.actionTimestamp(pending)` executes one `SystemClock.elapsedRealtimeNanos()` read, stores the immutable reply and wakes its sender. It returns that same integer immediately. The test immediately performs the original `cancelAndJoin`, `session.lock`, VPN disconnect or Tor kill, in its original context. No ADB completion, host ACK, file I/O, sleep or further await is inserted between the timestamp and action. The receiver only finishes the clock reply; it never invokes the action. A bounded asynchronous response must finish only after the sample exists.
5. The helper stamps `time.monotonic_ns()` immediately before starting the sample command and immediately after its completion, preserving stdout, stderr and original status. Both endpoints enclose the actual sample read, including all ADB/Android scheduling overhead. A nonzero status, timeout, empty reply, wrong result code or malformed result is fatal. `SAMPLE` must complete in at most one second; a successful proof additionally requires its measured bracket to be no wider than **100 ms**. These constants are fail-closed limits, never targets achieved by discarding slow successful replies.
6. A duplicate, late, wrong-identity or already-consumed `SAMPLE` poisons the case; no second action or replacement calibration is possible. All pending results expire after one second. The test stores the exact canonical reply bytes/digest in its receipt together with the returned counter. Retain all host attempts and errors. Unregister/close the receiver and thread in `finally`; host stops/joins its exact owned helper before collection/window end. Helper failure is separately preserved and prevents proof, without replacing the original Gradle status.

Apply to all six destructive phases, including VPN loss. Calibration never creates a remote-close claim for VPN loss. Ready polling may precede a phase; a sample cannot precede its arm or be reused from another phase/run. Finite waiting before the action is permitted; the peer reader remains continuously active and the final pre-action liveness checks still reject an already failed request.

## Exact interval and causal checks

Use host nanoseconds for new data. Decode existing host float timestamps exactly and round **outward** (for example, use the float's exact rational value); never round an upper bound down. Reject booleans as numbers, nonfinite values, negative/reversed times and integer overflow/type substitution. No midpoint is computed.

For a phase let `A` be the unchanged action counter, `Ds/Dr` the existing device arm send/receive counters, `Ha` the existing host arm monotonic time, `Hs/Hr` the new host request bracket, and `C` the unchanged genuine host close observation. Let `m = 5,000,000 ns`, preserving the current safety margin.

```
require 0 < Ds <= Dr <= A <= request_failed_elapsed_ns
require sample_elapsed_ns == A                 # exact same read, not nearby
require 0 < Hs <= Hr and Hr - Hs <= 100,000,000
I_arm   = [Ha + A - Dr - m, Ha + A - Ds + m]  # original arm upper unchanged
I_probe = [Hs - m, Hr + m]
I       = [max(I_arm.low, I_probe.low), min(I_arm.high, I_probe.high)]
require I.low <= I.high
require C >= I.high
require C >= I_probe.high                      # conservative independent guard
```

The last guard is intentional: although the intersection may narrow the probe, the proof never relies on an unestablished relative host/device rate to lower the independently demonstrated probe upper bound. Usually the narrow probe is contained in the wide Tor arm interval and both upper bounds coincide. The original arm remains mandatory admission/liveness/identity evidence and a consistency constraint; missing/disjoint evidence fails. This is stronger than using the intersection alone. It needs **no new clock-rate, affine-offset, midpoint or cross-clock suspend assumption**: monotonic host send/receive enclose the same Android read used for `A`. Calibration age relative to `A` is exactly zero. A device reboot/process replacement invalidates identity; device or transport delays while the host monotonic clock advances widen its measured bracket. Linux host monotonic may exclude host suspend; the proof compares the same host monotonic domain and does not infer a wall-time deadline from that clock alone. Host monotonic resolution must be observed and <=1 ms, covered by the retained 5 ms margin; host boot must remain identical. Device quantization is shared by the one read, not estimated from another clock.

The existing meaning of action timing is retained: the counter is read immediately before invocation, not a claim about the exact kernel arrival time of FIN. Never claim this proves causation against an adversarial independently closing peer; it proves the existing controlled-fixture observation ordering, plus local liveness and actual failed-after-action. Keep actual failure within20 s, host-close interval after arm within60 s, epoch/order/window checks, exact tokens and genuine EOF/reset/broken-pipe rules. Timeout, normal completion and generic TLS error still fail. For VPN loss retain the existing explicit unavailable-after-path-loss contract and controlled host drain separation.

## Implementation concretizations (review minors)

Boot IDs are bounded direct reads of `/proc/sys/kernel/random/boot_id`, strict lowercase UUIDs, independently in the instrumentation target process and selected `adb -s SERIAL` transport. Permission denial fails with no shell/root fallback on Android. Broadcasts target explicit `--user USER` and `-p uk.co.traynor.privategallery.hiddenprototype`; UID/user/package and runner class are checked in-process. `PendingResult` result-setting and finishing have one HandlerThread owner; cancellation, timeout and close converge there. Receiver/thread shutdown is nested in the outer route cleanup `finally` and runs under `NonCancellable`. Exact `Fraction` comparisons retain the original close float's rational value and never round C upward.

The existing shell runner invokes the new helper as a synchronous owner of the original timeout/Gradle child and one sampler thread. This keeps process wait/join ownership local and records Gradle, collection, clock and peer-close statuses separately. Its internal CLI is `evidence179_clock.py --case CASE --source-sha SHA --output app/build/evidence179/clock/CASE -- ORIGINAL_COMMAND...`; the frozen route validator CLI is unchanged. Each directory requires invocation/lifecycle JSON, all sequential command raw stdout/stderr pairs, the complete commands JSONL and both original/clock status text files. Proof replay accepts relocated raw directories while validating the recorded original helper output argument; existing packet/capture relocation constraints are unchanged.
