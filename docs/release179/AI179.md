# Optional owner-consented evidence analysis

This adapter provides optional OpenAI Responses analysis. Offline evidence, OCR and incident work do not depend on provider availability. No request is made while preparing a preview. The owner must configure their own API key in the originating vault, connect an approved immutable route, review the exact selected text and explicit images, and invoke the separate send action. Analysis remains advisory with `applied=false`; applying links or timeline entries requires the controller/UI's separate audited owner action.

## Integration API

Package `uk.co.traynor.privategallery.core.evidence`; adapters and their capabilities are internal.

```kotlin
val credentials = EvidenceCredentials(context, capturedAccess, onRemoved = { retirePreviewAndRoute() })
credentials.isConfigured()                 // Captured access required; no decrypted key read.
credentials.setup(ownerSuppliedChars)       // Run on IO; caller wipes its input/UI field.
credentials.remove()                       // Run on IO; revokes active disposable send keys.

val preview = EvidenceAi.prepare(
    catalog, selectedIds, imageIds = emptyList(),
    model = EvidenceAi.Model.LUNA,
    task = EvidenceAi.Task.FACTUAL_SUMMARY,
    sourceReader = capturedAccess.reader(), route = connectedRoute
)
// Show preview.exactText, images, owner, model/task, routeLabel/identity,
// estimatedUsd, pricingRevision/rates and disclosure before the send button.
val result = EvidenceAi.analyze(preview, credentials) {
    EvidenceEgress.digest(currentCatalog)
}
```

Both suspend operations perform their blocking work on IO. The digest callback executes synchronously on IO and must describe the authoritative current catalogue, including its revision/corrections. It is checked repeatedly, including immediately before and after the network call and before returning a result. Publish/save results only through the captured controller/access authority. Any change to selection, model, task, catalogue/corrections or route must retire the old preview in UI; a new selection needs a new preview and owner send action. There is no persistent consent grant.

`EvidenceAiPreview : AutoCloseable` exposes immutable owner/revision/catalogue digest, selected IDs, explicit image IDs, source fingerprints, model/task, route label/identity, exact body digest/size, consent digest, pricing revision, estimated USD and disclosure. `exactText` returns all transmitted input text, including the instructions, task framing, JSON content delimiters and selected fields. The private exact body bytes are retained unchanged until send. `images` contains exact transmitted JPEG descriptors (`evidenceId`, MIME, width/height, encoded byte count and SHA256). `copyThumbnail()` gives the UI an independent copy of that exact JPEG; the UI owns, clears and recycles its copies. Close the preview on dismissal, background/lock/Hide/Panic, changed selection/model/task/route, or catalogue changes. A consumed preview closes its route in its final cleanup. The route coordinator must observe this closure and release/reset its underlying owned services; its optional `onClose` callback can do that.

Owner/reader/route equality is explicit and checked before source reads. Only directly selected record name, description, notes, tags, participants and current transcript are included. Source filename claims, source paths/URIs, embedded metadata, GPS/EXIF, unselected records, incidents/retained incident notes, and earlier AI analyses are not added. The exact selected fields are visible in the preview. Every selected original, including text-only selections, is streamed to EOF and checked for the recorded size and SHA256 inside the owner-bound authenticated reader. Prepared images are not published until `readVerified` returns after its authentication/live-state checks. `EvidenceEgress.requireAllowed(..., VaultEgress.AI)` runs during prepare and immediately before/after send. A restricted, changed or unavailable selected original blocks the request. Incident-derived content is intentionally outside this direct-record API; a future incident input requires all retained contributing lineage to pass the same policy.

## Bounds, tasks and provider request

Select 1–32 distinct records, at most 8 explicit images from those records, and at most 100,000 selected-content characters. Images default off. Image source input is bounded to 32 MiB; dimensions are inspected before sampled decoding (100 MP source maximum, sampled working edge at most 2048). Each explicit image is drawn into a fresh white-background bitmap, resized to longest edge at most 1024 and JPEG encoded at quality85 into a bounded 2 MiB output. No original image metadata is copied. GIF/animated formats use the platform decoder's single image, not an automatic animation upload. No image/PDF/text temporary file is written.

The request is bounded to 20 MiB, response to 2 MiB and final advisory output to 100,000 characters. Oversize selected text/body/output is rejected instead of silently changing the consent payload. Complete strict JSON grammar is validated before Android JSON parsing: only JSON whitespace/double-quoted strings/strict numbers/literals/delimiters, no comments/single quotes/trailing input/duplicate decoded keys/unpaired surrogates, and bounded characters, values and nesting. Outer Responses depth is at most32, structured output depth at most16 and values at most100,000. Output arrays and structured references have independent bounds. Controlled fixture tests do not call OpenAI or use account credentials.

Tasks are factual summary, grouping, ordering, possible duplicates, structured event extraction and timestamp conflicts. Structured extraction asks for selected evidence IDs, exact visible date/time quotations, source-claim provenance, explicit uncertainty and null unknown fields, without invented participants/timestamps/time zones. Every output_text must be exactly one strict JSON object with exactly summary (string), suggestions (array) and events (array), with no wrappers/prose/fences/multiple blocks. There is at most one output_text. Suggestions have exactly kind/evidence_ids/title/reasons; events have exactly evidence_ids/title/date_time_quote/provenance/uncertainty. Their citations must be distinct nonempty selected-ID subsets; all fields have type/length/count checks. Unknown fields, foreign IDs and incident IDs are rejected. Advisory content remains separate from any application workflow; model prose cannot establish truth, verify byte identity, or authorise a change.

The only production endpoint is the exact constant `https://api.openai.com/v1/responses`, with POST, `store:false`, `background:false`, `stream:false`, `reasoning:{effort:"none"}`, `max_output_tokens:2048`, `tools:[]`, one user text input and only explicit `input_image` data URLs with `detail:"high"`. There are no Files API uploads, remote image URLs, tools or previous-response IDs. The body is structurally JSON encoded. No POST retry is performed. The one-shot consent is consumed before the first key read; failed or cancelled sends require a fresh preview.

Analysis.text is a strict JSON object preserving accepted summary/suggestions/events values (serialized formatting can change), with an app-owned _receipt containing status/refusal/cachedInputTokens/advisory:true/label. The model cannot supply _receipt. Its serialized characters count toward the final100,000-character limit; oversize is rejected. Completed, incomplete and refusal content are explicitly labelled in that advisory receipt. A valid incomplete response with no text is labelled as having no available analysis text. Input/output token usage comes from the response; cached input token usage is separately labelled in the receipt. Selected IDs, lineage, model, task, body digest and time are computed locally. Error bodies are discarded by real routes. Provider/network/parser failures carry fixed local messages without request bodies, URLs, keys or provider bodies. Success text/refusal that contains the actual key, including JSON-escaped echoes, is rejected before constructing an Analysis. Refusal wording is discarded after the key-echo check and replaced by a fixed safe refusal summary. No analysis automatically edits originals, transcripts, incidents or timelines.

`EvidenceAi.details(analysis): EvidenceAi.Details` is the read-only typed API for UI/export interpretation. It uses the same strict grammar, exact schema and allowed analysis.evidenceIds checks, and separately validates the app-owned receipt (including bounded usage and regenerated fixed label). Details exposes summary, suggestions, events, status, refusal and cachedInputTokens. StructuredSuggestion exposes kind/evidenceIds/title/reasons; StructuredEvent exposes evidenceIds/title/dateTimeQuote (nullable)/provenance/uncertainty. Collections are defensive unmodifiable copies. There is no UI-side permissive parser or apply operation. Root must retain full Analysis lineage even when applying a selected subgroup after separate owner review.

## Model costs and retention disclosure

The release reconnaissance checked official OpenAI documentation on 2026-10-31. These are approximate standard USD rates per million tokens, not a promise that current account pricing or availability is unchanged:

| Model | Input | Cached input | Cache write | Output |
| --- | ---: | ---: | ---: | ---: |
| `gpt-5.6-luna` | 0.20 | 0.02 | 0.25 | 1.20 |
| `gpt-5.6-terra` | 2.00 | 0.20 | 2.50 | 12.00 |

The preview estimates all framed text as `ceil(characters/4)` tokens and images as `ceil(ceil(width/32) × ceil(height/32) × 1.2)` each. It uses the higher cache-write input rate (1.25× uncached input), assumes no cache hit, and includes all2048 maximum output tokens. Characters/4 is approximate and is not a conservative token upper bound for every language. Neither this estimate nor the output bound is a hard account spending cap. Rates, account terms and returned actual usage can differ. Pricing revision is `2026-10-31:5.6-standard-usd` and is bound into the consent digest.

`store:false` does not establish zero retention. The confirmation disclosure states default abuse-monitoring content retention up to30 days, exceptions and account-specific controls, and that API data is not used for training by default absent opt-in. The owner transfers selected content to OpenAI. Owner-supplied on-device credentials reuse the existing AndroidKeyStore-backed AES-GCM store, using distinct AAD/provider IDs `evidence-openai-179-primary` and `evidence-openai-179-hidden`. They never enter catalogue records, preview text or export. Setup/remove/send reads require the captured authentication gate. All AiCredentialStore consumers now fence shared-alias lookup/first creation with one process-wide monitor. The public one-argument constructor, original private-gallery-ai-provider-v1 alias, ciphertext filenames, existing key and provider AAD remain unchanged. An existing inaccessible/incompatible alias fails without replacement. Shared per-path/owner credential generations invalidate active keys across multiple accessor instances; remove/replacement cancels their bound route before cleanup. Mutable owned key/character/body/image/result byte copies are cleared in finally blocks. Java strings in UI/JSON/HTTP authorization and TLS/internal library buffers cannot be reliably erased; no complete process-memory erasure claim is made.

## Immutable routes

The factories accept resources already connected and verified by the root coordinator:

```kotlin
EvidenceNetwork.primarySystem(current: () -> Boolean): EvidenceRoute
EvidenceNetwork.ownedVpn(owner, context, network, current, onClose = {}): EvidenceRoute
EvidenceNetwork.tor(context, unixPath, current, onClose = {}): EvidenceRoute
```

Only the Primary owner may use its explicitly authorised existing system-transport policy. Primary system transport uses Android system DNS/proxy routing; it does not bypass an OS VPN. Hidden must never select this factory. Owned VPN requires actual live VPN capabilities owned by this process UID and a link interface, pins `network.socketFactory` and `OwnedVpnDns`, rejects onion names and nonpublic DNS results, and has no default DNS/proxy fallback. Tor is Hidden-only and requires an app-private, same-UID filesystem Unix socket under the app data directory with an owner-only parent directory. It uses existing `HiddenVpnProxy.tor` (`TOR_ONLY`) and its authenticated numeric-loopback HTTP CONNECT bridge, with origin DNS prohibited and no TCP SOCKS port fallback. Root owns Tor/isolation startup, existing readiness checks and Android permission/service lifecycle. No browser profile, WebView setting or cookie policy is changed.

Each route has a random immutable identity, fixed owner/client and a current guard. Routes use default TLS, no redirects, no cookie jar/cache, no connection-failure retries, one-shot request bodies, no origin authentication retry, fixed timeouts and bounded reads. HTTP/1.1 avoids cross-origin HTTP/2 coalescing. Call check/create/register and close share one admission monitor. Retirement cancels every admitted call before proxy teardown and then invokes `onClose`; a short monitor also cancels calls when the captured guard becomes invalid. Coroutine cancellation cancels/disconnects the admitted call. The primitive accepts controlled HTTPS fixtures; only the AI adapter selects the exact production URL. There is no production TLS trust override. Fixture TLS uses its own disposable pinned certificate and private reflection entirely in `androidTest`.
