## Implemented scope

- Nova Backup entry in Home's built-in catalogue, Home settings and native Settings security section. Responsive scrollable protected modal uses the existing owned-window Panic wrappers.
- Primary and independently authenticated Hidden flows capture their originating authority. A Primary backup never enumerates Hidden stores. The first encrypted manifest binds the originating Space; foreign-Space archives and foreign/stale restore plans are rejected. No PIN/Keystore key/browser credential/session export.
- Portable `NOVABK01` archive: independent random 256-bit archive key, existing scrypt RecoveryEnvelope wrapping, symmetric recovery whitespace normalization, 64KiB AES-GCM frames, header digest/sequence/type/size AAD, encrypted metadata and per-item SHA-256/length endings, authenticated final entry-count/total completion, exact EOF required. Format reader range 1..1 and explicit NovaOS 1.7.11.6 minimum, with later 1.7.x eligible only when reader format 1 is supported (the frozen code61 release has no reader). UI generates a random high-entropy recovery key; no weak-passphrase security claim.
- Full-resolution active and Recently Deleted images, videos and documents stream through existing source verification and are re-encrypted under the destination's independent key. Restore allocates fresh item IDs, including duplicate filenames, and adds collections and membership using remapped IDs. Recently Deleted source items return as **active copies**, preventing retention expiry from deleting recovered data.
- One final repository index commit exposes each media batch. Pre-publication failure leaves existing index/media unchanged. Hidden promotes each ciphertext payload under a short authority commit, syncs, then commits metadata; cancellation does not wait through one giant payload-promotion monitor. After publication is attempted, uncertain durability retains ciphertext for inspection rather than deleting possibly referenced content.
- Audited settings namespaces: `nova_preview_v1`, `nova_mind_v1`, `nova_shell_v1`, `nova_widgets_v1`; `nova_arcade_v1` and `nova_calculator_v1` are reserved pending their actual codec validators. Only the current profile is serialized. Quick Note text is included encrypted; other widget configuration is stripped. Supported wallpaper bytes are re-encrypted. Authentication/concealed-entry namespaces and arbitrary framework preferences are excluded.
- Settings restore prepares an encrypted directory, syncs staged files and directory, then performs a recoverable directory swap. Startup recovers an interrupted rename. Explicit replacement confirmation is required; successful settings restore locks the Space so stale remembered Home/Mind/widget models cannot overwrite the restored data.
- Saved normal web-app definitions use existing encrypted catalogue stores, fresh identifiers and additive URL conflict handling. Existing app/session IDs and browser profiles remain untouched. Queries/fragments are excluded to avoid token-bearing entrypoints; UI discloses the resulting entrypoint difference. Restore definitions first, then settings to remap Home shortcuts; missing app shortcuts are omitted. The app's bundled Store catalogue remains bundled.
- Local SAF provider plus disabled descriptors for future WebDAV/S3/self-hosted transport. Encryption stays above the provider boundary. Export builds private ciphertext, copies it to the selected document, reopens actual provider bytes, fully authenticates them and compares the entire ciphertext SHA-256 before recording success. Provider errors never become verified receipts.
- Restore first copies to a bounded private ciphertext snapshot, validates the entire archive, then previews content/count/date and separate media/settings/app actions. Plaintext media never lands in a staging file. Keys/buffers are wiped where practical; ciphertext staging is removed on retirement and stale process-crash staging is cleaned on the next coordinator creation.
- Encrypted bounded 20-event history distinguishes verified/failed/interrupted-unverified operations and keeps a separate last-successful-backup receipt. Restore does not overwrite that receipt. Destination, bytes, date and verification are visible; media storage usage is shown.
- Optional Android JobScheduler daily/weekly due checks, charging/Wi-Fi constraints, due/next-due display. They deliberately hold no recovery key, destination URI or vault authority. They report **Needs unlock** and require an explicit foreground archive run. There is no unattended Hidden scheduler and no claim of automatic locked backup.
- SAF picker handoff retains metadata only; recovery input/generation happens after resumed fresh same-auth authority. Lock/reunlock or Space change invalidates the pending request. Ordinary close of a borrowed test/fallback capability does not close the retained Home authority.

## Explicit exclusions and limits

Evidence Locker catalogue/records/reports are not exported/restored by this checkpoint. Its immutable audit-chain successor checks and source-lineage bindings cannot safely accept a generic replacement or map to new recovered media IDs; this needs a dedicated lineage-preserving import design, rather than bypassing audited invariants. This is disclosed in the UI and encrypted manifest.

Gallery dates, collection pins and Primary crop/undo ledgers are included after review round 1. Collections include names, covers and membership. Favourite designation is included in the archive and can fill an unset destination favourite only after explicit checkbox confirmation; an existing destination favourite always wins. Gallery sort and retention remain destination choices. Hidden editing produces derivative media copies (included as media), not a separate crop ledger; a nonempty Hidden crop ledger is rejected rather than silently dropped. Other browser profiles, sessions/cookies/credentials, native security settings, non-note widget configuration and disposable/transient caches are excluded. Reserved Arcade/Calculator namespaces reject nonempty values until B/C registers their actual schema validators.

Limits are 10,000 media items per archive, 8GiB per item, 100GiB aggregate payload, 8MiB per settings record and 64MiB aggregate settings. Collection metadata is capped at 8MiB. Export checks its item/collection/settings descriptors against restore eligibility before writing the provider. Exceeding a limit fails the operation; items are never silently skipped.

Media, settings and app definitions are **separate explicit transactions**, not a global atomic restore. Repeating media restore makes additional copies. Settings replacement cannot reconstruct an excluded category. Provider-wide atomic rename is not universally available through CreateDocument; failed export may leave an incomplete destination document, explicitly reported. Free-space exhaustion is handled by staged IO failure and existing-data preservation; no provider free-space promise is made. JVM Strings from Compose/JSON cannot be deterministically zeroized; key arrays and practical working buffers are wiped.

## Review round 1 — I1–I4 repairs

The independent review is `/tmp/nova62-backup-review.md`; the binding scope is recorded in NOVA62_PROGRESS.md. No production release or native-runtime acceptance is claimed by this repair checkpoint.

- **I1:** `PortablePreferenceSchema` checks exact scalar types, finite numeric ranges, supported Home profile/page/folder/wallpaper structure, current-owner Mind records and widget geometry/configuration before any staging. Unknown supported-record fields and nonempty unimplemented app schemas fail closed. The real SpaceContext harness passes wrong-typed `reduced` and an empty Home page list through the binary archive-value interface and verifies every existing ciphertext file remains byte-for-byte identical after rejection. Each staged encrypted settings record is also decrypted and compared before directory promotion.
- **I2:** `SettingsDirectoryTransaction` distinguishes a durable committed receipt from an incomplete directory swap. It syncs staged ciphertext and the parent, checks current authority, then writes/syncs a commit receipt under the final short authority fence. Promotion, parent-sync, retirement and receipt-sync failures roll the original directory back; a secondary recovery failure retains prior ciphertext and is attached to the original error. Restart with old/new but no valid receipt chooses the old directory; a committed receipt chooses the new tree. The prior tree is only renamed to a cleanup path after that decision, so interrupted recursive deletion cannot masquerade as a usable rollback copy. The receipt records the commit decision, rather than a hash of the changing tree: recording backup history after success legitimately changes its ciphertext. Native process-kill/filesystem durability still requires the consolidated run.
- **I3:** Primary restore passes its captured authority predicate into legacy image/document encryption, legacy readback, chunked-video encryption and chunked-video readback, and checks again immediately before promotion. Deterministic JVM tests revoke after a real readback chunk, prove no final payload/stage remains, and prove the input closes. Existing Reader `use` closes the random-access file and wipes its owned key/cache; encryption/verification working buffers are wiped. Original JVM overloads and Kotlin default bridges remain delegates, preserving baseline fixture linkage.
- **I4:** media metadata carries added/captured/adjusted/modified dates and validated timezone. Collections carry pin state, remapped cover/membership/favourite relationships and remapped Primary normalized crop/one-step undo values. New item and collection IDs preserve destination conflicts. The favourite opt-in only fills an unset favourite; existing favourite/sort/retention choices remain unchanged. Imported dates/pins commit atomically with the Primary v7 index or optional Hidden metadata fields. Primary writes v7 only when these optional fields exist; v1–v6 reads do not rewrite any bytes or keys, and ordinary snapshots without presentation values retain v6. Subsequent local date resets and explicit unpin operations override imported values through the existing presentation store.
