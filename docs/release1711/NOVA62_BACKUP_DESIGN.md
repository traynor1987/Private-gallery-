# Nova Backup checkpoint A design

The authority is the captured current SpaceContext/EvidenceAccess, never a stored key or Space flag. Primary and authenticated Hidden use the same screen separately. Primary UI/history/catalogue contains no Hidden discovery or combined backup option. Background scheduling can request an unlocked foreground run but cannot retain recovery credentials or sensitive authority.

The portable format encrypts each bounded record with AES-256-GCM using a new random archive key wrapped by the existing scrypt recovery envelope. Header digest, sequence and frame type are authenticated. Metadata, item lengths/hashes and final completion are encrypted. A valid final frame and exact EOF are required. The UI generates a high-entropy recovery key; human-entered recovery material is normalized consistently. No Android Keystore key is exported.

Document providers are untrusted. Backup creates a private ciphertext artifact, copies it to the selected document, reopens and authenticates actual destination bytes and compares a complete ciphertext digest before recording verified success. Provider failure leaves a visibly incomplete/unverified document, never a false success. SAF cannot guarantee atomic promotion across providers.

Restore copies selected bytes into a bounded private ciphertext snapshot, authenticates the entire archive before presenting a preview, then consumes that same snapshot. All data is re-encrypted under the destination Space authority. Media restores are additive: unique IDs preserve duplicate filenames; a single index publication exposes the completed media batch. Existing media and collections must survive any pre-publication error. No destructive replacement is offered. Decrypted media must never be staged as plaintext. Cancellation checks cover source/destination IO, cryptography and publication. Immutable snapshot handles are closed on retirement.

Category support is explicit. Home/Mind/preferences use a named, audited allowlist, never a directory sweep. Credentials, cookies, authentication settings and concealed entry sequences are excluded. Evidence catalogue restore cannot bypass its audited successor rules; unsupported categories are disclosed in the encrypted manifest and UI. Any narrower implementation or pending runtime coverage is documented in the final evidence report.


Review-round repair decisions: application schema validation precedes encrypted staging. Settings replacement uses a durable commit receipt and retains the rollback directory until recovery has a committed decision; failure after promotion restores the old tree. Media readback accepts the same cancellation authority as source IO. Remapped gallery dates/pins live inside the atomic Primary index v7 / Hidden metadata publication rather than a separate presentation-store transaction. Prior index versions remain readable without eager migration. Existing presentation overrides still take precedence, and favourite recovery requires opt-in without replacing an existing favourite.
