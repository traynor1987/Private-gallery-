# Owner-private Android native fence foundation

This is an independently named JNI boundary for the reviewed persistent TUN fence and disposable WireGuard transports. It is **not active Android service integration, authentication, child-death proof, readiness provenance, or C1 acceptance**. The active GoBackend remains unchanged. Never initialize this owner while the original backend's independent Go runtime is loaded. The package-private Java class is unreferenced by current runtime code.

## Build

Linux x86_64: `./gradlew :app:prepareContinuousVpnNative` builds all four ABIs under `app/build/generated/continuousVpnJni`. The generated source directory is attached to every variant (debug and release). AGP resolves/provisions NDK `27.2.12479018` through `sdkComponents.ndkDirectory`. Existing release signing guards remain unchanged.

For local tools, set `NOVA_GO_ARCHIVE` to the original Go1.20.3 Linux AMD64 tarball and `NOVA_GO_ROOT` to its extraction with the checked-in upstream CLOCK_BOOTTIME patch. The script verifies the archive hash, patch hash, exact Go version and every original distribution file against the archive with only that patch allowed. Without overrides it downloads/verifies/prepares those sources under the Gradle build directory. Direct script invocation accepts output directory and NDK directory as its two positional arguments. Wrong explicit toolchains, hashes or NDK revisions fail closed. No prebuilt libraries are checked in. Upstream source notices remain under `../upstream`.

The native libc ABI baseline is API21, independent of the APK's unchanged API37 requirements. All four final ELFs must have >=16KB LOAD alignment and congruent offsets, SONAME `libnova-wg.so`, and only the independently prefixed expected JNI methods. The build script verifies those actual outputs.

## Owner contract

`NativeVpnFence.create(originalPfd, trustedMtu, trustedName)` retains Java's original protective descriptor. Java owns a temporary duplicate throughout the native call and closes it in `finally`, including failure before JNI entry. JNI immediately creates its own `F_DUPFD_CLOEXEC` duplicate; the C layer closes that duplicate on pre-Go errors and transfers it exclusively to `Registry.CreateFD` otherwise. Go consumes it on every result. Before os.File adoption only the raw duplicate is closed; after adoption only that os.File closes it. There is no upstream Name ioctl/error/finalizer ambiguity. Descriptors must already be nonblocking; shared descriptor flags are never changed. Exactly one native reader owns the lifetime TUN. Transport retirement never closes it.

Return convention: positive long = opaque handle/epoch/sequence, 0 = success, -1 invalid, -2 denied, -3 concurrent control busy, -4 failed, -5 exhausted. Handles in the single JNI owner registry never repeat; transport handles differ from per-fence generation numbers. All values must fit positive signed longs. At exhaustion admission cannot reopen by wraparound.

Only `epoch`, `sequence`, `publish`, `invalidate`, and `invalidateTransport` are monitor-safe. They use immutable atomic snapshot registry lookup and atomic current pointers; no registry/configuration/owner mutex, Java callback, TUN I/O, or close. All other methods may block and must run outside authentication/session/security monitors. The owner must capture epoch in the authenticated admission transaction and carry it unchanged to `replace`; a worker must not refresh stale authority. Per-fence control uses a nonwaiting busy CAS; concurrent replace/retire/release returns BUSY. It is not held by monitor-safe invalidation and is never a Java/publication mutex.

`replace` accepts strictly newer generation, captured epoch, 64-character hex private/public keys, optional empty-or-64-character preshared key, numeric endpoint, 1–16 comma-separated canonical allowed prefixes, and bounded keepalive/listen port (0–65535). No arbitrary UAPI, DNS, URL, key or exception text leaves JNI. Malformed/stale requests preserve the current generation. A replacement starts CLOSED. Its immutable epoch/fence identity is stored with it, its pointer is published before the final epoch check, and fence-wide invalidation increments epoch before reading/invalidation of that pointer. Errors retain sealed reachable ownership until retirement.

The synchronous `Protector.protect(fd)` callback must call only the owner's `VpnService.protect(fd)`. It cannot reenter the bridge or session/owner APIs. Native configuration and socket FD-lifetime locks intentionally cover it. JNI attaches/detaches only threads it attaches, clears Java exceptions and denies protection, and retains the global reference until corresponding callbacks and retirement finish. If JVM teardown prevents attachment for deleting a reference, the C allocation/reference is retained rather than freed unsafely.

`beginProbe`, `register`, and `publish` require the current transport and matching replacement epoch. Generic `register` only wraps exact numeric TCP/UDP tuple leases; it does **not** prove kernel source-port ownership or authenticate parent packet provenance. The rejected Java kernel reservation design is not used here. The REAL lifetime-TUN path now requires OPEN at enqueue, dequeue and write, even for a registered tuple. Registration grants no REAL PROBE aperture. A structurally separate parent-private producer, inbound demultiplexing, retirement and late-response collision protection remain necessary before readiness can work. Later readiness integration remains separately reviewed work. `remove` recognizes only the exact fence/transport/epoch/lease and returns success after removing future admission or proving that generation permanently sealed; it is not a drain receipt.

`retire(fence, transport)` acknowledges blocking retirement without closing lifetime TUN. `retireCurrent(fence, originalGeneration, originalReplacementEpoch)` rejects stale cleanup without touching a newer current generation; it is the cleanup path after `replace` returns failure/denial without a new transport handle. `release(fence, allSensitiveChildrenDead)` alone may close the lifetime TUN; false denies. The boolean is an explicit external proof assertion by the future trusted owner, not a native inference about authentication/process death. Any retirement error retains containment and cannot produce a successful release receipt.

`statistics` returns exactly `[status, handshakeSeconds, handshakeNanos, rxBytes, txBytes]`, using a bounded internal UAPI writer that never exposes its raw secret-bearing result. Numeric fields must fit signed longs. This accessor blocks and is not monitor-safe.

## Verification scope

Host tests exercise the real reviewed gate/transport/WireGuard device through fake TUN/bind boundaries: cross-owner/stale handles, tuple/epoch validation, failed replacements, revocation before construction/during blocked protection/between pointer publication and final epoch comparison/after replacement, callback ownership, concurrent publication/close lookup, signed exhaustion, and sole FD adoption/close. No Android instrumentation, actual VPN routing or child-lifetime ordering is claimed. Successful retirement atomically detaches each heavy transport/protector payload after the actual Close barrier, clears matching lease payloads and the bridge current pointer, and leaves numeric-only authority/removal receipts. Existing readers keep immutable local payload references until their calls end; the implementation never unsafely nils a field concurrently read by another goroutine. The reviewed transport owner also forgets only that same successfully closed current device; its registry high-water mark continues to reject stale generations. Its existing child cleanup already follows device shutdown and gate drain.

The registry has a practical global cap of **4,096 total entries**, including live fences/transports/leases, pending reservations, retired transport receipts and removed-lease receipts. Replacement reserves capacity before destructive work; full capacity returns EXHAUSTED while preserving the existing current generation. Handles still never repeat. Exact known removal receipts remain idempotent until successful final fence release. Final release atomically detaches the core fence and removes all owner metadata/reservations, restoring capacity; unknown/foreign/reclaimed handles cannot claim old receipts. A long-lived owner that reaches the receipt cap must handle exhaustion and obtain the externally proven final-release conditions before starting a fresh lifetime. There is no automatic lifetime release or direct fallback.

Failed or blocked barriers retain their precise heavy payloads and callback references. If construction fails and its internal teardown also fails, transport Replace returns that exact partial transport with the error; the bridge keeps its nonnil payload and callback. Core final release propagates any remaining transport-barrier error before marking the fence released or closing its lifetime TUN. A failed final TUN close remains a sticky failed release; a later call cannot turn the upstream already-released shortcut into a successful bridge receipt. Reclamation tests use real Transport/Fence finalizers to prove former device/lifetime objects become collectible while the registry remains alive, including repeated replacements/removals/releases and concurrent lookup/reclamation. This is reference-lifetime control, not comprehensive JVM/Go secret zeroization.

JNI replacement initializes its private/preshared-key C buffers and funnels all exits through a single cleanup label. A noinline volatile-byte wipe survives optimization; focused host tests compile the actual JNI implementation with test-only function instrumentation and cover malformed later arguments, callback failure and the transferred-call return. The Android build contains no test hooks. Optimized final-ABI code must still contain both cleanup calls and the wipe stores. Only these owned C stack copies are wiped; caller-owned Java strings, Go copies, compiler registers or arbitrary historical heap bytes are not claimed to be comprehensively zeroized.
